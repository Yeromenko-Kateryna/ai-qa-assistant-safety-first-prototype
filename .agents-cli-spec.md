# AI QA Assistant — Target Agent Specification

> **Status: designed target specification.** The deterministic core and mock demo are implemented, but the live three-agent workflow described here is not. For current capability, see [release status](docs/release_status.md).

## Target Purpose

The target system helps junior and middle QA engineers turn pasted English product requirements into a structured QA draft for human review. It is designed to extract stated facts, identify missing information and risks, design traceable tests, propose automation recommendations without code generation, and provide QA review.

## Target Input and Output Scope

- Input: pasted English plain text only; no files, URLs as data sources, issue trackers, screenshots, or live API contracts.
- Output: versioned canonical JSON containing safety metadata, requirement analysis, risks, test design, automation recommendations, QA review, stage statuses, and safe errors.
- Presentation: deterministic Markdown derived from safe canonical JSON without a second model call.

## Target Workflow

1. Pre-provider input safety gate.
2. Requirement Agent.
3. Risk & Test Design Agent.
4. QA Review Agent.
5. Deterministic candidate aggregation.
6. Schema, reference, and resource validation.
7. Output safety gate.
8. Deterministic Markdown rendering.

The workflow is designed to be sequential. Each model stage is intended to produce an atomic typed output that must validate before downstream use.

## Target Safety Constraints

- Raw input is processed at the pre-provider safety boundary.
- Only sanitized input may enter invocation-scoped state.
- Requirements are untrusted data, not executable instructions.
- Agents are designed to have no shell, browser, repository, filesystem, external API, code-execution, or MCP tools.
- Candidate output must pass structural, referential, resource, and safety validation before presentation.
- Partial reports are intended to be marked incomplete and fail target release evaluation.

## Target Success Criteria

- A complete local workflow runs without manual agent switching.
- Three scenarios—complete requirement, incomplete requirement, and injection attempt—pass the defined release gate.
- Independent rubric-based evaluation reaches the approved thresholds.
- Deterministic tests cover contracts, provenance, resource limits, redaction, enrichment, and rendering.

These are target success criteria, not achieved-release claims. No project-specific live orchestration or semantic-evaluation result is included in this repository.
